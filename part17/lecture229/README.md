## この講義の問い

ブロックチェーンはなぜ遅いのか。ブロックの上限を上げれば速くなるのか。速くなった分の仕事は誰がするのか。スケーラビリティの方策を見るとき、何から問うべきか。

## 実習資料

### 準備

二つを使う。

- `fill`：新しいストレージの欄をn個書く講義用のコントラクト`Fill229`一つ。Foundryプロジェクトではなく、solc 0.8.30で直接コンパイルする（`solc --optimize --bin --abi`、警告なし）。デプロイと呼び出しはanvil（`--hardfork osaka`）にcastで行う。anvilは3回立ち上げる：デフォルトの設定、`--enable-tx-gas-limit`（取引一つのガス上限をオン）、`--gas-limit 300000000`（ブロックの上限を十倍）。
- `market`：通しプロジェクトMarketの第179講のバージョンそのままである。コードは変えず、新しいanvilにデプロイして最初の預け入れのガスだけを測る。forge-stdが必要である。

外部のチェーンには接続しない。アカウントはanvilのデフォルトのテスト用アカウントである。

### 実行結果

anvil `--hardfork osaka`の0番ブロック：ブロックのガスリミット30,000,000、ベースフィー1,000,000,000 wei。Fill229のデプロイは120,059ガスである。

| 呼び出し | gasUsed | 欄一つあたり |
|---|---|---|
| fill(1) | 65,920 | 65,920 |
| fill(100) | 2,256,817 | 22,568 |
| fill(1000) | 22,329,529 | 22,330 |

取引一つの基本の21,000と`next`の欄への書き込みは、nが大きくなるほど埋もれる。欄一つ約22,330のうち、大部分は0の欄に初めて書く値22,100である。

`eth_estimateGas`の二分探索で見つけた、上限30,000,000に収まる最大のnは1,343である。取引のガスリミットをブロックの上限より大きく与えると、最初から拒否される：

```
$ cast send <Fill229> "fill(uint256)" 1393 --gas-limit 31000000 ...
Error: server returned an error response: error code -32000:
intrinsic gas too high -- tx.gas_limit > env.block.gas_limit
```

ブロックを受け取ったノードがすること（取引をもう一度実行する）を`cast run`で見ると、最初と同じガスが出る：

```
$ cast run <fill(1000)の取引ハッシュ> --rpc-url <RPC_URL>
...
Gas used: 22329529
```

ブロックの上限を十倍に上げたanvil：

```
$ anvil --hardfork osaka --gas-limit 300000000
$ cast send <Fill229> "fill(uint256)" 10000 --gas-limit 290000000 ...
```

0番ブロックのgasLimitは300,000,000で、fill(10000)はgasUsed 223,073,629で2番ブロックに取引一つとして入る。

Marketの最初の預け入れ（新しいanvil、第179講のバージョンのコードそのまま）：デプロイ701,941 → addAsset 92,632 → 最初のdeposit 100 127,516 → withdraw 30 55,289ガス。

| | 上限30,000,000 | 上限300,000,000 |
|---|---|---|
| 1ブロックの新しい欄 | 最大1,343 | 10,000（223,073,629ガス） |
| Marketの最初の預け入れ | 30,000,000 ÷ 127,516 ≈ 235回 | 2,352回 |

`anvil_dumpState`が出す状態のコピーのバイト数：

| チェーン | 書く前 | 書いたあと |
|---|---|---|
| 上限3千万、新しい欄1,101個 | 2,887バイト | 46,120バイト |
| 上限3億、新しい欄10,000個 | 2,895バイト | 371,583バイト |

取引一つのガス上限（EIP-7825、16,777,216）をオンにしたanvil：

```
$ anvil --hardfork osaka --enable-tx-gas-limit
fill(700)  → gasUsed 15,655,729 通過
fill(1000) → intrinsic gas too high -- tx.gas_limit > resolved tx gas limit cap
fill(1000) --gas-limit 23000000 → 同じ拒否
```

オプションなしで立ち上げたanvilでは、fill(1000)の22,329,529が通る。

### 試すときの注意

- ブロックの上限はanvilのオプション一つで変わる。同じノートパソコンで上限を十倍に上げると、1ブロックに入れる仕事も十倍になるが、ブロックを受け取ったノードがやり直す計算と持っている欄も十倍になる。
- `anvil_dumpState`の大きさは、圧縮したコピーのバイト数である。実際のノードのディスクの大きさとは違い、取るたびに数バイトずつ変わる。新しく書いた欄は消えずに状態に残る。
- anvilは、osakaハードフォークでも取引一つのガス上限をデフォルトではオンにしない。`--enable-tx-gas-limit`を与えて初めて、16,777,216を超える取引を拒否する。
- 長さが伸びるリストを1回の取引で全部回る関数（受け取る人全員に送るpayAllのようなもの）は、上限を超えた日から、どんなガスを与えても失敗する。分けて処理するか、受け取る人がそれぞれ取りに来るようにするか、まとめる長さを上限の内側に収める。

## 時効性のあるデータ

基準日時点の値。ツールのバージョンとメインネットの設定が変わると変わることがある。

| 項目 | 値 | 基準日 |
|---|---|---|
| Foundry（anvil・cast） | 1.8.3、commit cae51ad4 | 2026-10-21 |
| solc | 0.8.30+commit.73712a01 | 2026-10-21 |
| anvil osakaのデフォルト値 | ブロックのガスリミット30,000,000、ベースフィー1,000,000,000 wei | 2026-10-21 |
| メインネットのブロックのガスリミットの提案 | EIP-7935原文14行目 "The gas limit on mainnet is currently 36M. This should be significantly increased to 60M by the time Fusaka is released by execution layer clients updating their default configurations."（クライアントのデフォルト設定の提案。実際の値はチェーンで確認） | 2026-10-20 |
| ブロックの間隔 | 12秒（スロット基準）と仮定。235 ÷ 12 ≈ 19.6回/秒 | 2026-10-21 |
| 取引一つのガス上限 | 16,777,216（2^24）、EIP-7825 | 2026-10-21 |
| Fusaka（EIP-7607）のメインネットでの有効化 | 2025-12-03 21:49:11 UTC、エポック411392 | 2026-10-21 |
| EIP-4844 | Final、2022-02-25作成 | 2026-10-20 |
