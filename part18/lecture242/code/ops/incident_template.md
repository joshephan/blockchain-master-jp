# 事故記録 (Market)

## 1. ヘッダー
- 事故番号 / 等級(1・2・3) / 状態(対応中・停止維持・終了)
- 最初に気づいたブロックと時刻、気づいた経路(監視の警報・ユーザーの申告・外部からの通報)
- 事故の責任者(決める人) / 調査 / 署名者への連絡 / 外への通知 / 記録
- 役割ごとの連絡先、連絡がつかないときに代わりに連絡する人

## 2. 等級の基準
- 1等級: 預けたお金が今出ていっているか、引き出す量がトークン残高 + 貸し出した借金より大きい(不足分が生じる)。すぐ停止、署名者全員を呼び出す
- 2等級: まだ失ったお金はないが不変条件が一つ崩れた、または出金の試し呼びがPanic・未知の失敗でふさがれた(HIGH)。停止するかを署名者二人が決める
- 3等級: 管理者の行動・状態変更の通知、監視自身の故障(ノード停止、周回停止)、送信キューの停止、ドキュメントに書いた失敗でふさがれた出金の試し呼び(LOW: 貸し出した分・借金の上限)。勤務時間内に確認

## 3. タイムライン (ブロック番号順、ops/timeline.pyの出力)
| ブロック | 時刻 | 起きたこと | tx |
|---|---|---|---|

## 4. ここまでに分かっていること / 分かっていないこと
- 分かっていること(ブロック番号・txハッシュで)
- 分かっていないこと

## 5. したこととその取引
- 停止: 提案番号、実行した署名者、tx、ブロック
- 送ったアカウント・ナンス、同じナンスで署名したハッシュ全部(手数料を上げて送り直したものを含む)
- 署名前のcalldataの確認: ほどいて読んだ関数と引数

## 6. 外に知らせた文 (送った時刻ごとに一つの欄)
- 分かっていること / したこと / ユーザーが今できること / 次の通知時刻

## 7. 事後報告
- 影響: 誰がいくら引き出せないか(アカウントごとの持ち分、不足分)
- 原因: 間違った前提一行(信頼の前提リストのどの行か)
- 再現するテスト: テスト名と結果
- 気づくまでにかかったブロック数、止めるまでにかかったブロック数
- 直すもの: コード(次の版)、監視(新しい検査)、手順(この様式)
