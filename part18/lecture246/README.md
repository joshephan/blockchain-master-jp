## この講義の問い

何を「ふだんと違うこと」とみなすかを、どう決めるのか。クエリが見つけてくれたことは誤りなのか。クエリは何を防ぎ、何を防げないのか。

### 試すときの注意

- デコードされた表は、申請したアドレスのログだけを入れる。同じtopic0を別のアドレスが出した行は、元のlogsの表でアドレスの条件を外して探さないと見えない。
- 大きな値が一つ混ざると、平均は大きく揺れる。ふだんをつかむときは中央値も一緒に見る。
- リバートした取引はlogsにない。リバートの理由は表に欄がないので、取引を再実行して読まなければならない。
- これらのクエリは、ブロックに入ったあとのものだけを見る。ブロックに入る前（メモリプール）の段階で前もって見る監視は扱っていない。
- [246-3]の取引のハッシュは、取引のガスリミットが見積もりの値なので、Marketのバージョンが変わると変わる。ブロック番号と帳簿・金庫の値は同じである。

## 時効性のあるデータ

基準日時点の値。時間がたつと変わることがある。

| 項目 | 値 | 基準日 |
|---|---|---|
| Foundry（forge・cast・anvil） | 1.8.3 (cae51ad4) | 2026-10-21 |
| solc | 0.8.30 (optimizer 200、via-IR、osaka、ipfs・cbor)、コードの末尾 0x00081e | 2026-10-21 |
| Duneのアラート | メール・Webhook、予約実行のクエリに付く、実行後に送信・遅れることがある・配信の再試行なし、"not recommended for time-sensitive or critical applications at this stage" | 2026-10-21 |
| Duneのデコード（プロキシ・ダイヤモンド） | プロキシは、プロキシのアドレスに実装のABIで申請する | 2026-10-21 |
