## この講義の問い

互いを信用しない1万台前後のコンピューターが順番に合意するには、何をあきらめなければならず、その代償として何を得るのか。

## 実習資料

### 準備

Node.jsだけあればよい。ブラウザーの開発者ツールのコンソールで試しても結果は同じである。

### 実行結果

`node -p`で浮動小数点の足し算を確かめた出力（node v24.11.0）。同じ式でも、浮動小数点の結果は期待した値とずれることがある。

```
0.30000000000000004
```

`0.1 + 0.2 === 0.3`の結果：

```
false
```

## 時効性のあるデータ

基準日時点の値。時間がたつと変わることがある。

| 項目 | 値 | 基準日 |
|---|---|---|
| ビットコインの毎秒の処理件数 | 約8件（24時間で695,298件 ÷ 86,400秒） | 2026-10-20 |
| イーサリアムメインネットの毎秒の処理件数 | 約20件（直近24時間のブロック300個の標本、ブロックあたり平均240.8件 ÷ 12秒） | 2026-10-20 |
| ビットコイン・イーサリアムのノード数 | ビットコイン25,155台（bitnodesの到達可能ノード） / イーサリアム11,955台（Etherscan Node Tracker、直近24時間に検出） | 2026-10-20 |
| 取引所ごとの入金反映の基準ブロック数 | BTC Bithumb 1 / Binance 1（出金解除 2） / Coinbase 2 / Upbitは公開ページにコンファメーション数なし・ETH Bithumb 33 / Binance 6（出金解除 64） / Coinbase 14 / Upbitは公開ページになし | 2026-10-20 |
| イーサリアムのフルノードの推奨ディスク容量 | 最低2TB NVMe SSD、推奨4TB（EIP-7870）。実行クライアントのsnap syncでGeth 500GB+、Nethermind 500GB+、Besu 800GB+、合意クライアントで約200GBを追加 | 2026-10-20 |
