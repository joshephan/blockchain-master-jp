## この講義の問い

0xで始まるアドレス一行はどこから出てくるのか。そして、そのアドレスを「持つ」とは、正確には何を持つという意味なのか。

## 実習資料

### 準備

Foundryの`cast`だけあればよい。秘密鍵1（`0x`と0を63個、末尾に1をつけた32バイトの値）からアドレスを計算する。送金はせず、計算だけをする。

### 実行結果

`cast wallet address --private-key <秘密鍵1>`の出力、秘密鍵1のアドレス：

```
0x7E5F4552091A69125d5DfCb7b8C2659029395Bdf
```

`cast wallet public-key --private-key <秘密鍵1>`の出力、公開鍵64バイト：

```
0x79be667ef9dcbbac55a06295ce870b07029bfcdb2dce28d959f2815b16f81798483ada7726a3c4655da4fbfc0e1108a8fd17b448a68554199c47d08ffb10d4b8
```

その公開鍵を`cast keccak`に入れた出力。最後の20バイト（`7e5f45...395bdf`）がアドレスである：

```
0xc0a6c424ac7157ae408398df7e5f4552091a69125d5dfcb7b8c2659029395bdf
```

`cast to-check-sum-address 0x7e5f4552091a69125d5dfcb7b8c2659029395bdf`の出力、大文字と小文字が混ざったチェックサムつきアドレス：

```
0x7E5F4552091A69125d5DfCb7b8C2659029395Bdf
```

EIP-55の照合用に、小文字のアドレス40文字を文字列としてハッシュした`cast keccak "7e5f4552091a69125d5dfcb7b8c2659029395bdf"`の出力：

```
0xa8aaec6aceafa450816b295770adcd144ce18d630d6ce74288aa4f1569eda4ca
```

ハッシュの2文字目の8 → アドレスの2文字目のeがE、4文字目のa → fがF、12文字目のf → aがA、18文字目の1 → dは小文字のままである。ハッシュの文字が8以上なら、その位置のアドレスの文字を大文字で書く。

### 試すときの注意

- 秘密鍵1は誰でも知っている鍵である。このアドレスに本物のお金を送ると、すぐに他人に持っていかれる。
- チェックサムは打ち間違いを捕まえるだけで、まったく別だが有効なアドレス（アドレスポイズニングで仕込まれた偽アドレスなど）は捕まえられない。
