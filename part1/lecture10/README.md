## この講義の問い

第1講で、順番を決める権利には対価を取ると述べた。ビットコインはその対価をどう取り、その対価でどれだけ安全になるのか。

## 実習資料

### 準備

Node.jsだけあればよい。外部パッケージは使わない（組み込みの`crypto`モジュールを使う）。時間（ms）はマシンや実行のたびに変わるが、試行回数とハッシュは同じ入力ならいつも同じになる。

### コード

| ファイル | 内容 |
|---|---|
| [code/mine.js](code/mine.js) | おもちゃのマイニング。sha256ハッシュが0でk桁始まるまでナンスを上げながら試し、試行回数と時間を測る（k = 1〜5） |
| [code/verify.js](code/verify.js) | データとナンスを受け取り、ハッシュ一回で確かめる |
| [code/wp11.js](code/wp11.js) | ビットコインのホワイトペーパー11節の攻撃者成功確率の式を移して計算する |

`node verify.js 'prev:0000abcd|alice->bob:10' 968381`と、データの10を11に変えた同じコマンドの出力。見つけるには96万回かかったが、確かめるのはハッシュ一回で、データが一文字違うだけで条件から外れる。

```
00000cad6b51e595647af06571d29763f3b9d83fb20947aacd6949800a3962e2
9f5f9c497ee8ab42ba3cd2536d32e604648e2b85db2637ec57213573ad91add3
```

`node wp11.js`で計算した攻撃者の成功確率（qは攻撃者のハッシュパワーの割合、zは追いつかなければならないブロック数）。ホワイトペーパーの表にある値とすべて一致する。攻撃者30%のz=1、2、3はホワイトペーパーの表（5ブロック間隔）になく、同じ式で計算した値である。

```
0.1 1 0.2045873    0.3 1 0.6277491
0.1 2 0.0509779    0.3 2 0.4457171
0.1 3 0.0131722    0.3 3 0.3245841
0.1 5 0.0009137    0.3 5 0.1773523
0.1 10 0.0000012   0.3 10 0.0416605
P < 0.001: q 0.1 → z 5, q 0.2 → z 11, q 0.3 → z 24, q 0.4 → z 89, q 0.45 → z 340
```

上の表は、出力から一部の行を選んで二列にまとめたものである。`wp11.js`をそのまま実行すると、z = 0〜6、10のすべての行と、q 0.1〜0.45のzが一行ずつ出る。

### 試すときの注意

- ブロックヘッダーのナンス（マイニング用の数字）とアカウントのナンス（送ったトランザクションの通し番号）は、名前が同じだけの別の値である。
