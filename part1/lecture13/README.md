## この講義の問い

第12講の「アドレスからアカウントへのマッピング」全体をどうやってハッシュ一つに要約し、その値を一つ変えると何が起きるのか。

## 実習資料

### 準備

Foundryの`anvil`（ローカルのテストチェーン）と`cast`だけあればよい。送るアカウントはanvilの既定アカウント0番（公開されたテスト用の鍵）、受け取るアカウントはanvilの既定アカウント1番（`0x70997970C51812dc3A010C7d01b50e0d17dc79C8`）である。受け取るアカウントに1 ETHずつ二回送ってブロック1、2を作り、ブロックごとに`cast block <ブロック> -f stateRoot`でステートルートを、`cast proof <受け取るアカウント> -B <ブロック>`でアカウントの証明を取る。証明のノードごとに`cast keccak`でハッシュを計算する。

各証明の最初のノードのハッシュが、そのブロックのstateRootと同じである。下のノードのハッシュは、すぐ上のノードのバイトの中に入っている（最初のノードの0番の枠、二つ目のノードの0番の枠）。二つ目のブランチノード（83バイト）は0番の枠と13番の枠の二か所だけが埋まったノードで、0番の枠が受け取るアカウント側である。リーフノードの中に、アカウントのキー（keccak256（アドレス））の後ろの部分、残高、storageHash、codeHashが入っている。

### 試すときの注意

- anvilの0番ブロックのヘッダーのstateRootは空のツリーのルート（`0x56e8…b421`）と表示され、実際のアカウントツリーのルート（0番ブロックの証明の最初のノードのハッシュ`0x00db56fd…9752`）と違う。そのため、送金一件で作ったブロック1番から始める。
- ステートルートと証明ノードの値は、ローカルチェーンの状態によって変わる。
