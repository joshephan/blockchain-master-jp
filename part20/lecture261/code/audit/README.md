# 自己監査 (レンディングマーケット)

読む順番: scope.md(範囲の表) → known-issues.md(既知の問題) → design/architecture.md 6節(信頼の前提) → コード。報告書はself-audit.md

## 等級の基準(監査の前に決める)
| 等級 | 影響と条件 |
|---|---|
| High | 信頼の前提が全部守られても預けたお金を失うか奪われる |
| Medium | 信頼の前提が一行崩れると預けたお金を失う、または前提が守られても引き出しの道が止まる |
| Low | 失う量が丸めの数単位、またはドキュメントとコードが違って読む人が誤解する |
| Info | お金と機能に影響なし。ドキュメント・形・ツールの警告 |

## 候補の選別
見つけたものごとに三つを問う: 範囲内か、known-issues.mdにあるか、お金や機能が実際に損なわれるか。三つとも通ったものだけが発見事項
候補はテストで再現されるまでは候補。再現 = 直した版で通る確認テスト(test/Findings.t.sol)が今の版で失敗
