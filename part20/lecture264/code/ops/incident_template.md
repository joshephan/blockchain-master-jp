# 事故記録 (Market)

## 0. 最初の30分の手順
1. 警報を見た人が決める人(1節)を呼ぶ。決める人が等級(2節)を決めて記録を開く
2. 止めるかを決める。停止の道は、資産ごとに事前に承認しておいたpause(資産, 3)の提案を署名者一人がexecute(提案番号)。署名の前に提案の宛先アドレス・calldataをほどいて読む
3. 使った停止の提案はもう使えない(AlreadyExecuted)。同じ資産の新しい提案を作り、署名者二人が承認しておく
4. 原因を探す人がMarketの外(価格の出どころのオペレーター、トークンの発行体、ノード)に連絡。Marketの中には出どころ・トークンを変える関数がない(D-13)
5. 外に知らせる人が最初のお知らせ(6節)。ユーザーが今できることを先に書く
6. 再開はタイムロック2日(unpauseの予約)。予約した作業idを監視の予定ファイルに書く

## 1. ヘッダー
- 事故番号 / 等級(1・2・3) / 状態(対応中・停止維持・再開・終了)
- 最初に気づいたブロックと時刻、気づいた経路(監視の警報・ユーザーの申告・外部からの通報)
- 決める人 / 原因を探す人 / 署名者を集める人 / 外に知らせる人 / 記録
- 役割ごとの連絡先、連絡がつかないときに代わりに連絡する人
- 外部の連絡先: 資産ごとの価格の出どころのオペレーター、トークンの発行体

## 2. 等級の基準(事故の前に決め、事故中に変えない)
- 1等級: 預けたお金が今出ていっているか、引き出す量がトークン残高 + 貸し出した借金より大きい(監視の残高CRITICAL)、ログなしで金庫のトークンが減る(照合CRITICAL)。すぐ停止、署名者全員を呼び出す
- 2等級: まだ失ったお金はないが、価格の出どころがリバートするか平均が追いついている途中(価格HIGH)、不変条件が一つ崩れた(合計HIGH)、出金の試し呼びが未知の失敗でふさがれた、予定にないタイムロックの予約。決める人が停止するかを決める
- 3等級: 設定の通知(INFO)、監視自身の故障(ノード停止、周回停止)、ドキュメントに書いた失敗でふさがれた出金の試し呼び(LOW)、ログなしで入ってきたトークン(LOW)。勤務時間内に確認

## 3. タイムライン (ブロック番号順、ops/timeline.pyの出力)
| ブロック | 経過(秒) | 起きたこと | tx |
|---|---|---|---|

## 4. ここまでに分かっていること / 分かっていないこと
- 分かっていること(ブロック番号・txハッシュで)
- 分かっていないこと

## 5. したこととその取引
- 停止: 提案番号、実行した署名者、tx、ブロック。新しく承認しておいた提案番号
- 再開: タイムロックの作業id、予約ブロック、実行可能時刻、実行ブロック
- 送ったアカウント・ナンス、同じナンスで署名したハッシュ全部(手数料を上げて送り直したものを含む)
- 署名前のcalldataの確認: ほどいて読んだ関数と引数

## 6. 外に知らせた文 (送った時刻ごとに一つの欄)
- 分かっていること / したこと / ユーザーが今できること / 分かっていないこと / 次の通知時刻
- ユーザーができることは、Marketがどの状態でも開けている道で書く: 引き出し、返済、担保のオフ(S-01)。価格の出どころが止まった資産は設計文書6節のT-01の文のとおり

## 7. 事後報告
- 影響: 誰がいくら引き出せないか(アカウントごとの持ち分、不足分)、清算されたアカウント
- 原因: 間違った前提一行(信頼の前提リストのどの行か)
- 再現するテスト: テスト名と結果
- 気づくまでにかかったブロック数、止めるまでにかかったブロック数
- 出たものごとに答えを一つ: 修正(コードは次の版・監視・手順) / ドキュメントをコードに合わせる / 設計どおり(根拠)
