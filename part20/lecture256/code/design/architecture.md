# 設計文書 (レンディングマーケット)

要件はdesign/requirements.md。この文書がコードより先に決めるもの: ストレージスロット、誰が何を呼ぶか、何を信頼するか、常に成り立つべき文。コードはこの文書の順番を移す

## 1. 構成と境界
| 部品 | すること | 境界 |
|---|---|---|
| Market (src/Market.sol) | 帳簿、利息、上限、清算 | IMarket(ABI)一つ |
| MarketMath (src/MarketMath.sol) | 利率曲線、利息、丸めの計算。internal関数だけ | Marketのランタイムコードの中(別のデプロイ・リンクなし) |
| MarketTypes (src/MarketTypes.sol) | ストレージスロットの構造体、価格の出どころのインターフェース | 型だけ |
| 価格の出どころ (Marketの外) | 累積した価格の合計 | IPriceFeed.cumulativePrice一つ。桁数・古さ・複数の出どころの確認は出どころ側のコード |
| トークン (Marketの外) | ERC-20 | balanceOf, transfer, transferFrom, decimals |
| キーを握るアカウント (Marketの外) | 設定キー | アドレス一つ(コンストラクタ引数) |
| 運用ツール (チェーンの外) | インデクサー、監視、送信キュー | イベントと読み取り関数(O-01、O-02) |

## 2. ストレージスロットの地図
スロットごとにそのスロットに書く関数を一緒に書く。書く関数を書けないスロットは置かない

| スロット | 名前 | 欄 | 書く関数 |
|---|---|---|---|
| 0 | assets (address[]) | 長さ、keccak256(0) + i | listAsset |
| 1 | assetConfig[asset] | keccak256(asset . 1) 二スロット。+0 feed(オフセット0~19)・decimals(20)・collateralRatio(21)・pausedBits(22)・listed(23)、+1 supplyCap | listAsset, setSupplyCap, pause, unpause |
| 2 | reserves[asset] | keccak256(asset . 2) 五スロット。+0 scaledDeposits、+1 scaledBorrows、+2 supplyIndex、+3 borrowIndex、+4 lastAccrual | +0 deposit・withdraw・liquidate、+1 borrow・repay・liquidate・writeOffBadDebt、+2~+4 利息の積み上げ(状態を変えるすべてのユーザー関数)、+2 writeOffBadDebt |
| 3 | positions[asset][user] | keccak256(user . keccak256(asset . 3)) 三スロット。+0 scaledDeposit、+1 scaledDebt、+2 useAsCollateral | +0 deposit・withdraw・liquidate、+1 borrow・repay・liquidate・writeOffBadDebt、+2 setCollateral |

- immutable(ランタイムコードの中、スロットなし): admin(設定キー)、rateAtKink(折れ点の年利率)
- 持ち分(scaled)に指数を掛けるとトークン量。指数0は1と読む
- 前の版との違い: マーケット一つの状態の欄(status)なし(資産ごとにpausedBits)、最終更新時刻の欄(lastUpdate)なし、合計の欄二つがreservesの中へ、価格の出どころの欄がassetConfigの中へ、金額の型(Amount・Rate・Ratio)と付けた演算子なし

| 関数 | 呼ぶ側 | 停止の影響 | 外部呼び出し | 要件 |
|---|---|---|---|---|
| listAsset | 設定キー | - | decimals、cumulativePrice(読み取り) | F-10, A-02 |
| setSupplyCap | 設定キー | - | なし | A-02 |
| pause | 設定キー(停止だけをするキーを別に置くことはA-03) | - | なし | A-03 |
| unpause | 設定キー | - | なし | A-04 |
| deposit | 誰でも、自分の欄 | 預け入れ停止ならActionPaused | transferFrom | F-01 |
| withdraw, withdrawAll | 誰でも、自分の欄 | なし | transfer、担保なら価格の読み取り | F-02, S-01 |
| setCollateral | 誰でも、自分の欄 | なし | オフにするとき価格の読み取り | F-03, S-01 |
| borrow | 誰でも、自分の欄 | 借り入れ停止ならActionPaused | transfer、価格の読み取り | F-04 |
| repay | 誰でも、自分の借金 | なし | transferFrom | F-05, S-01 |
| liquidate | 誰でも | なし | transferFrom、価格の読み取り | F-07, S-01 |
| writeOffBadDebt | 誰でも | なし | 価格の読み取り | F-08, S-01 |

設定キーでできることは四つ。その四つにトークンを移す関数はない(A-01)。表にない状態を変える関数はない

## 4. 順番と丸め
- 状態を変える関数の順番: 確認(金額0、上場した資産、停止) → 利息の積み上げ → 現金・預け入れの上限の確認 → 帳簿の修正 → 借金ができるか担保が減るなら上限の確認 → トークンの移動 → イベント(S-02)
- 丸め(S-04): 渡す預けた持ち分・担保の値・受け取る担保・引き出す量は切り捨て / 借りた持ち分・借金の値・返す量・引く預けた持ち分は切り上げ
- 利息(F-06): 指数二つ(預け入れ側supplyIndex、借り入れ側borrowIndex)。時間がたったときだけ上がり、同じブロック内ではそのまま、貸し出した持ち分がなければそのまま。利率曲線は折れ点80%までrateAtKinkに向かって直線、超えると年100%の傾き
- 価格(F-09): 出どころの累積合計二つ(今、30分前)で平均。記録が30分より短い出どころは上場でリバート
- 清算(F-07): 清算ライン = 担保の値 × (担保比率 + 5)。一度に借金の50%まで、担保の値が借金より小さければ借金全部まで。受け取る担保 = 返した値 × 1.05、預けた量より多ければ預けた量に減らし、返す量も減らす
- 借金の消去(F-08): 担保の値が0のアカウントの借金だけ。消した量だけ預け入れ側の指数を下げる。消す借金が預け入れの合計以上ならLossExceedsDeposits

## 5. 不変条件
| 番号 | 常に成り立つべき文 | 確認 |
|---|---|---|
| I-1 | 金庫のトークン + 貸し出した借金 ≥ 預けた人が引き出す量の合計 | S-03、ランダムな順番のテスト |
| I-2 | 資産ごとにscaledDeposits = アカウントのscaledDepositの合計、scaledBorrows = アカウントのscaledDebtの合計 | ランダムな順番のテスト |
| I-3 | 借り入れ側の指数は下がらない。預け入れ側の指数は借金の消去でだけ下がる | ランダムな順番のテスト |
| I-4 | borrow・withdraw・担保のオフが成功した直後、そのアカウントの借金の値 ≤ 借入上限 | F-03, F-04 |
| I-5 | 引き出し・返済・清算・借金の消去・担保のオフは停止とキーに関係なくできる | S-01 |

## 6. 信頼の前提
- T-01 価格の出どころ: 資産ごとに一つ、上場時に決め、変える関数なし。Marketは出どころが返した合計をそのまま信頼する。出どころが止まると、その資産を担保に使うアカウントの借り入れ・担保の引き出し・清算が止まり、返済はできる
- T-02 トークン: ERC-20、decimalsあり。受け取るとき申告した量がそのまま入ったかはMarketが数える(S-07)、送るとき受け取る側が少なく受け取るのはトークンの責任。発行体が凍結できるトークンは発行体の鍵も信頼する。ブリッジで渡ってきたトークンはそのブリッジの検証モデル・鍵・金庫も信頼する
- T-03 ブロックの時刻: 利息と平均のウィンドウはblock.timestamp(ブロックを作る側が書く値)
- T-04 順番: 同じブロック内の順番はブロックを作る側が決める(同じアカウントの清算は先に入った一つだけ)
- T-05 清算する側: ボーナス5%がガスと受け取った担保を売るときの損より大きくないと誰も呼ばない
- T-06 キー: 8節
- T-07 コンパイラ・ライブラリ: solc 0.8.30(D-01)、OpenZeppelin Contracts 5.4.0のファイル四つ(D-10)
- T-09 アカウント: Marketは呼んだアドレスだけを見る。そのアドレスの裏の委任コード・セッションキーの範囲・復旧の仕組みはアカウント側が決める(セッションキーがMarketを呼べるなら受け取るアドレスは常にそのアカウント)
- T-08 ノード: 運用ツールは自分が問い合わせたノードが見せた値しか知らない

## 7. 攻撃の地図(草案)
| 軸 | 法則が届く行 | 防ぐもの | 確認 |
|---|---|---|---|
| 制御の移転 | トークンのtransfer・transferFrom、価格の出どころ・decimalsの読み取り | 帳簿を全部直したあと最後にトークン(4節)。価格の読み取りは状態を変えられない呼び出し | S-02 |
| 順番の操作 | 清算の競争、価格、利息の時刻 | 30分平均、同じブロック内では指数そのまま | F-09 |
| 資源と精度 | 上限計算のループ、割り算 | 資産20個の上限、丸めの方向(4節)、持ち分0の預け入れのリバート | S-04, S-05, S-06 |
| 中央の地点 | 設定キーの関数四つ | トークンを移すキーの関数なし、引き出しを止めない | A-01~A-04, S-01 |
| 暗号の材料の組み違え | なし(署名・証明を受け取る行なし) | - | - |

## 8. キーの表
| キー | できること | なくしたら | 奪われたら |
|---|---|---|---|
| デプロイアカウント | デプロイ。デプロイ後にMarketでできることはない | 影響なし | 影響なし |
| 設定キー(admin) | 3節の四つ | 新しい資産・上限・再開ができない。預けたお金は引き出せる | 偽の資産と偽の価格の出どころで預けたトークンを借りていく → A-02の待機時間 |
| 運用アカウント(監視・キュー) | Marketの権限なし。ナンスは一か所でだけ採番 | 送る仕事が止まる | そのアカウントのお金だけ |
| 価格の出どころのオペレーター | その資産の担保の値 | その資産を担保にした借り入れ・清算が止まる | 担保の値を上げて別の資産を借りていく。預け入れの上限は担保トークンの量だけを縛り、値は縛れない |
| ユーザーのキー | 自分の欄 | 自分の持ち分 | 自分の持ち分 |

## 9. 標準の対照表
| 標準 | 従うか | Marketでは | 理由 | 確認 |
|---|---|---|---|---|
| ERC-20 | 受け付ける | balanceOf・transfer・transferFrom・decimals。移動はSafeERC20(戻り値なしは通過、falseはリバート)、受け取るとき金庫の残高が増えた量を数える | 標準どおりに動くという前提をコードで減らす(T-02) | S-07, S-08 |
| ERC-20 decimals(OPTIONAL) | 必須 | listAssetが一度読む。なければ上場でリバート | 資産ごとに値の単位をそろえる | StandardsTest:test_decimalsReadOnce |
| 移すときに引くトークン・残高が勝手に変わるトークン | 受け付けない | 受け取るときにAmountMismatch | N-05 | S-07 |
| ERC-721, ERC-1155 | 受け付けない | decimalsがないのでlistAssetでリバート | 資産の欄はアドレス一つに同じ値のトークン一つ | StandardsTest:test_nonErc20Rejected |
| ERC-165 | しない | supportsInterfaceなし | この応答を読んでMarketを呼ぶ側がいない。応答は関数を呼んでみないと正しいか分からない | StandardsTest:test_noErc165 |
| ERC-4626(金庫の持ち分) | しない | 預けた持ち分は帳簿の欄、トークンでは渡さない | 持ち分が移動すると担保の欄と承認の経路が一緒に生まれる(N-02) | - |
| ERC-1967・UUPS(プロキシ) | しない | コードを変える道なし | アップグレードキー一つでコード全体が変わる(A-05)。新しい版は新しいアドレス、ユーザーは引き出して移す(S-01) | A-05 |
| EIP-2612(署名による承認) | 受け付けない | 承認はトークンのapproveの一つの道 | 署名を受け取る行をMarketに置かない | - |
| EIP-7702・コントラクトアカウント | 受け付ける | 呼んだアドレス(msg.sender)だけを見て、コードがあるかは見ない。withdraw・borrowに受け取りアドレスの引数なし(常に呼んだアカウントへ) | アカウント側の鍵の設計に関係なく同じ帳簿 | StandardsTest:test_delegatedEoaBatch, test_contractWallet |
| EIP-1271(アカウントの署名確認) | しない | 署名を受け取る行なし | - | - |

## 10. 決定記録
- D-01 言語・コンパイラ: Solidity 0.8.30一つ、srcのアセンブリブロック0個。根拠: 前の版を平らに移した版が同じテスト136個を通過、ランタイム9,043 / 9,006バイト(平らな版 / デプロイ版)、計った呼び出し六つのガスの差は48以下。手で書いたバイトも呼ぶときに節約できるガスは百ガスほど以内。ソースマップ・ストレージ配置の出力・バグリスト(bugs.json)・forgeのテストをそのまま使う。0.8.30の既知のバグとの照合は自己監査のとき
- D-02 ツール: forge(ビルド、テスト、fmt、lint、snapshot)。ci.shの六段階。ビルド設定は前の版の値そのまま(optimizerはオンでruns 200、via-IR、osaka、bytecode_hash ipfs)
- D-03 一つのコントラクト: 親・modifier・using for・付けた演算子なし。検査は関数の最初の数行、二か所以上で使う検査はinternal関数(_onlyAdmin、_config)。根拠: 上の平らな版、読む道が一つのファイルの上から下へ
- D-04 数値の定数(変える関数なし、講義用の設計値): 折れ点80%、その先の傾き年100%、平均のウィンドウ30分、清算ラインの間隔5、ボーナス5%、一度に返す借金50%、担保比率の上限80、資産20個
- D-05 価格: 累積合計二つで平均。即時の価格を読む関数なし
- D-06 資産数の上限20: 上限の計算が資産リストを全部回る。前の版で計った値: 資産2・20・100・500個で清算264,842・387,284・931,536・3,652,736ガス
- D-07 計算部品から: MarketMathをMarketより先に書き、曲線の表・利息・丸めの方向をテスト(test/Math.t.sol)
- D-08 上場は一度に: 価格の出どころ・担保比率・預け入れの上限をlistAsset一つで。価格の出どころなしで上場した資産がないように
- D-09 年利率の表示: borrowRateは今の借りた比率が1年中そのままとみなして計算した値
- D-10 取り込んだコード: OpenZeppelin Contracts 5.4.0(lib/openzeppelin-contracts、package.json version 5.4.0)からMarketが使うファイル四つ。sha256: token/ERC20/utils/SafeERC20.sol ee455e7a…08fc98、token/ERC20/IERC20.sol c8818310…f19341、token/ERC20/extensions/IERC20Metadata.sol a1ec1fe6…b6fa8、interfaces/IERC1363.sol e50076f7…59c619。読んだ関数: SafeERC20 safeTransfer(33)・safeTransferFrom(41)・_callOptionalReturn(173~191、アセンブリブロック176~186)。取り込んだあとsrcから呼ぶ外部呼び出しの場所: CALL 2 → 1(SafeERC20の一か所)、STATICCALL 4 → 6(金庫の残高を二回)
- D-11 remapping: 二行(forge-std、@openzeppelin/contracts)だけ書いて自動検出を切る(auto_detect_remappings = false)。メタデータに二行だけが入る
- D-12 受け取るときに数える: _pullがtransferFromの前後の金庫の残高の差を数える。預け入れ・返済のガスが1,867、清算が1,873増える(deposit 137,297 → 139,164、liquidate 233,854 → 235,727)
