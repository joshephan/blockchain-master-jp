# 要件 (レンディングマーケット)

## 一行
互いに知らない人たちがERC-20トークンを預け、預けたトークンを担保に別のトークンを借り、借金が担保を超えたポジションは他の人が清算するマーケット

## 判別フィルターの適用
使い方: 1番から順に答え、いいえが出たらその行で止める。反証は1~5番を全部通過したときだけ答え、はいなら脱落

| 番号 | 質問 | 答え | 根拠 |
|---|---|---|---|
| 1 | 一つの状態を共有すべき主体が二つ以上か? | はい | 預ける側、借りる側、清算する側が資産ごとに同じ帳簿(預け入れの合計、借り入れの合計、利息の指数)を見る |
| 2 | その主体同士が互いに敵対しうるか? | はい | 借りた側は担保の値を高く、借金を低く書く動機。清算する側同士が同じポジションを奪い合う |
| 3 | 全員が受け入れる第三者がいないか、その第三者自体がリスクか? | はい | 預けたトークンを握る仲介者がいれば、その仲介者が出金を止めるか持ち去る。互いに知らないアカウント同士がみな信頼する仲介者はいない。トークンの発行体・価格の出どころは第三者として残る(信頼の前提) |
| 4 | 記録の順番と事後の不変性が紛争で証拠として必要か? | はい | 誰が先に清算したか、利息がいつから付いたかがお金を分ける。ブロックに入った順番が根拠 |
| 5 | 前で数えたコストを払っても余るほどその価値が大きいか? | 条件付きではい | 前の版の記録: 預け入れ136,902ガス、借り入れ204,128ガス、清算264,842ガス(資産二つ)。金額が小さいと手数料が利息より大きい → 小さい金額のユーザーは目標から外す(N-08) |
| 反証 | 最終決定権の行き着く先が結局一つの主体の鍵か? | 前の版: はいに近い | 管理者の席一つ(マルチシグ三つのうち二つ)が資産の追加と価格の出どころを決める。その鍵で偽のトークンと偽の価格の出どころをつなげば預けたトークンを借りていける → A-01~A-05で直す要件 |
| 判定 | | 1~5は通過、反証はA-01~A-05を守った版で答え直す | |

## 入れないもの
| 番号 | 入れないもの | 理由 |
|---|---|---|
| N-01 | 同じ取引の中で借りて返す貸し付け(フラッシュローン) | 貸して返してもらう道が一つの取引にできると、指数・上限の計算をその取引の中で考え直す必要がある |
| N-02 | 預けた持ち分をトークンで渡す(持ち分トークン) | 持ち分が移動すると担保の欄と承認の経路が一緒に生まれる。再判断は標準の統合のとき |
| N-03 | 投票トークンとガバナンス | 設定キーはマルチシグと待機時間で。投票の道は作らない |
| N-04 | 価格の出どころの複数統合・予備の出どころ | Marketの外のアダプターの役目。Marketは出どころ一つを信頼する(信頼の前提) |
| N-05 | 移すときに手数料を引くトークン、残高が勝手に変わるトークン | S-07の確認でリバートする。上場しない |
| N-06 | プロトコル手数料の分 | 利息は全部預け入れ側へ |
| N-07 | アップグレード | A-05 |
| N-08 | 小さい金額のユーザー | 判別の質問5 |
